# CityPress 城市日报

都市：天际线 II 新闻模组，开发版 0.2.0-beta.5。已在本机游戏程序集上编译；尚未完成游戏内实测，不保证覆盖所有玩家动作。

## 使用

解压 `dist/CityPress-0.2.0-beta.5.zip` 全部内容到 `%USERPROFILE%\AppData\LocalLow\Colossal Order\Cities Skylines II\Mods\CityPress`，在本地模组环境启用。不要只复制 DLL，界面资源和 Templates 目录也必须安装。发行包不自动安装、不修改游玩集。

进入城市后点左侧报纸按钮，打开“编辑部设置”，输入 DeepSeek API Key 并保存。也支持启动游戏前设置 `DEEPSEEK_API_KEY`。密钥不会出现在城市存档、日志或界面状态回传中，输入框不会回显已保存密钥。

面板右上角持续显示当前游戏日期与时分秒，刷新频率为每秒四次，暂停时跟随游戏时钟停住，阅读历史报纸不会改用旧刊时间。城市时间尚未就绪时显示“正在同步”，不创建日志或调用生成接口。加载旧存档会移除初始化产生的 0001 年无效日期，历史列表也会过滤无效日期文件名。

默认不开启自动生成，后台仍记录操作。点“生成本日新闻”生成当前游戏日期的报纸；档案馆可以补编已记录的日期。开启每日自动发行后，在游戏日期前进时编印上一日期并弹出阅读面板。不会生成安装前或未观测到的历史日。运行中单次生成串行，自动任务按日期排队，失败后可手动补编。

报头留空时为当前城市名加“日报”；填写后使用自定义名称。设置可应用于当前存档，或设为全局默认并让当前存档继承；其他有独立设置的存档不受影响。可恢复全局继承。开关、报头、模型和编辑方针均随此范围应用。

## 内容与缓存

重复类别和详情合并，保留次数、首次和末次发生时间。取消 500 种操作截断，有效操作完整进入编辑素材；城市指标保存首值、末值、极值、采样次数和观测时间。完整汇总保留在本地和存档。模型根据可编辑方针自主决定栏目、篇数、合并与舍弃；不强制每日栏目与新闻事件。极端情况下素材超过单次编辑容量，会明确提示并保留全部本地记录，不静默删掉低频事件，也不发起付费请求。

本地成稿缓存包含存档标识、模型、编辑方针、城市名、报头、日期和事实汇总。相同事实直接读取成稿，只有采样次数增加、指标没有变化时也复用；事实变化会重新生成。固定提示前置、变化数据后置，以利用 DeepSeek 自动前缀缓存；实际命中取决于服务端，阅读页展示返回的命中和未命中 token 数，不能保证每次命中。

游戏暂停不会导致额外日刊；生成不阻塞游戏主线程。切换或重载存档会取消旧请求，旧请求结果不得发布到新会话。不同存档按保存于游戏存档内的随机标识隔离；从同一存档另存的分支继承该标识，因而共享本地档案目录，输入不同仍有独立缓存。

## 存储

根目录：`%USERPROFILE%\AppData\LocalLow\Colossal Order\Cities Skylines II\ModsData\CityPress`

- `settings.json`：全局编辑设置。
- `key.dpapi`：当前 Windows 用户加密的 API 密钥。
- `cities/<存档标识>/journal.index.json` 与 `journals/<日期>.json`：约每十秒后台更新当前日备份，历史日不反复重写；旧 `journal.json` 保留。
- `cities/<存档标识>/cache/`：通过验证的成稿缓存。
- `cities/<存档标识>/issues/<游戏日期>.json`：游戏内档案副本；`exports.json` 记录报纸实际导出位置。
- 系统文档中的 `CityPress/<报纸名称>/存档-<存档标识>/<日期>.docx` 与 `.json`：默认导出文件。同日期在同目录重新生成会更新当日期刊。文档位置跟随 Windows 重定向设置。

在“编辑部设置”的“报纸导出目录”填写完整文件夹路径，留空恢复默认；设置可应用于当前存档或全局。新目录用于后续导出，旧报纸保留原处；阅读历史报纸后，“打开导出文件夹”打开它的实际位置。“导出当前报纸”可将已有成稿另存到新目录，不调用 API。旧版 AppData 中的报纸仍可阅读和打开原目录。

日志和当前存档设置嵌入游戏存档。本地 journal 是额外备份，不会自动覆盖读取的游戏存档，避免读旧档时引入未来操作。Word 导出直接套用随包的 `Templates/newspaper.docx`，与游戏内报纸统一的纸色、左右版签、行楷报头、日期栏、正文分栏和随文版脚；可以在 Word 中调整模板样式。只有本地文件保存成功后才发布报纸。Word 不嵌入游戏截图。

## 采集范围与待验收事项

通用挂钩观察游戏 ToolOutputSystem 的 Apply 阶段，记录工具标识与预制体名称，覆盖经此管线提交的道路、建筑、分区、拆除、地形等工具动作。它不是逐实体的工程量测量，连续刷子可能产生多次提交，最终是否成功建成还需游戏内验收；不会把次数解释为道路长度或建筑数量。

当前版本接入原生管理按钮采集，涵盖符合管理动作规则的税务、预算、收费、政策、贷款、购地、设施升级/拆除/迁移、线路设置与手动改名。政策、设施等实体参数优先解析自定义名和本地化资产名。贷款记录的是申请调整后的目标总额，并另外观测实际余额，不把申请额写成新增借款。自动车辆状态与通用改名接口仍不监听；相机、选择、面板导航、预览、设置与账户界面不采集。原始读取器参数不会为记录而二次消费，无法展开的参数不猜测。

新增独立城市观测：在 ModificationEnd 检查建筑、路网边、区域、公共交通线路和树木实体的新增/移除；跨帧进行快照校对，完成后间隔 5 游戏分钟启动下一轮，观察施工、废弃、损毁、火情、政策、附属升级和线路票价/选项变化。载入现有城市先建立基线，现有设施不会被误报成新建。实体新增不保证投入运营，路网边不等于完整道路；不把自动生长与自动路网拆分归因于玩家。附属实体不重复计为独立设施，升级通过主建筑记录校对。

读取城市事件档案，保存事件进展、伤亡、损失和城市影响的累计观测，明确禁止把同一事件的累计值反复相加。基线前的旧事件不作为新发生事件；仍在进行的旧事件在数值变化时记录后续。

统计快照遍历当前游戏已登记的全部城市统计类别与参数，包含人口、经济、税收、就业、教育、健康、幸福、迁入迁出、治安、客货运、旅游等实际可用指标，同时保存原生样本与汇总值、统计口径和单位；另读市库、贷款余额、解锁用地、交通流畅度/流量、供电需求/供给/储能、供水与污水处理、气温及雨雪状态，以及空气/土壤/噪声污染栅格的平均、最高强度和非零占比。污染范围为全地图，不冒充城区人口暴露值或现实的 AQI、浓度、分贝。原生统计有自己的刷新周期；每 5 分钟读取并不意味着游戏数据也每 5 分钟更新。未解释的参数和单位可存档辅助核对，但不能编成新闻数字。

采集和刊发分开：有效素材先留存，编辑部再按新闻价值取舍；发送变化指标与人口/市库/贷款/用地等背景值，不把未变指标和原生单样本/汇总值重复塞进稿件。没有变化的快照不会单独触发生成。完整采集仅指已接入数据源的有效信息，不保证接管所有第三方模组内部动作。短于快照间隔的中间状态、没有通用提交入口的自定义操作、无法读取的内部数据可能缺失。兼容面板显示接入数量和采集异常，不把未确认内容当作覆盖成功。

需要在游戏内继续验收：新建/载入/另存、暂停跨日、多个日刊排队、切城取消、工具取消与失败提交、每类管理动作、第三方模组冲突、原生 Cohtml 下的滚动与弹窗。没有使用真实 API 密钥执行付费请求；网络协议、缓存和错误响应以可控替身测试。

## 重大突破与性能

检测常住人口、市库余额、月度预算总收入、月度预算收支结余、家庭数、当前在城游客和解锁用地的整级突破，以及月度预算由亏转盈。例如人口越过 40 万、45 万、50 万会形成事实素材；同一天多次越线合并保留最高一级。首次读取只建立基线，历史最高值随存档保存，数值回落后再涨回不会反复报。安装前或未观测区间的历史不追认，也不声称城市史上首次。无限资金显示值不作为财政突破。月度预算收入不是本月已结算收入，结余不是市库余额；原生单位未解释的数据不用于编造突破。

突破独立进入编辑素材和缓存；即使没有其他操作也可触发编报，默认仍只在手动点击后生成。模型必须将重大突破纳入正文，可与相关事件合并，避免逐条播报。

指标、事件、污染和实体校对分帧执行；报纸生成、Word 导出、档案读取和分日日志写入在后台执行。实时时钟独立更新，避免每次时钟跳动重绘整张报纸。兼容情况面板显示近期采集切片峰值耗时。分帧数量与时间目标不保证所有原生调用都在预算内：游戏任务等待、实体列表复制和大规模瞬时建设仍可能出现耗时尖峰，实际帧率需在真实存档继续验收。

安装 .NET SDK 与 Node.js，运行 `./build.ps1` 生成发行压缩包。可通过参数 `-ManagedPath` 指定游戏 Managed 目录；Harmony 开发依赖位于 tools/dependencies/0Harmony.dll，发行包同时包含此运行依赖。

`dotnet run --project Tests/CityPress.Tests.csproj` 验证聚合、默认手动、缓存复用与失效、存档隔离、无效响应和 Word 套版。

`npm run typecheck --prefix UI` 与 `npm run build --prefix UI` 检查界面。

界面参考本机 RouteFilter 源码的主题变量、54rem 标题栏、10rem 圆角、青色活动态、分段导航和内嵌表单。报纸正文使用统一纸色与游戏注册的中文字体，按相同规则分成一至三栏；Word 保留可编辑文字，长篇内容分页时可能产生换行差异。

接口依据：[DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/) 与 [Context Caching](https://api-docs.deepseek.com/guides/kv_cache/)。游戏挂钩针对本机程序集反射检查和编译，不依赖第三方事件模组。




旧日志保留，但生成时会重新过滤自动改名状态和没有具体内容的纯编号政策。没有资产的对象工具记录排除，拆除/地形/水体工具则按操作意图保留。筛选后没有有效动作也没有指标变化时，本地保存简短空刊，不调用 DeepSeek。筛选规则版本进入缓存键，旧版噪声成稿不复用。

0.2.0-beta.3 修复报纸中文方框与档案行分散排版，报纸改用游戏已注册字体。过去无操作、无指标的初始化日期从历史中移除，已误生成报纸只隐藏入口、不删除本地文件；真实早期日期和仅指标历史保留。Word 保留可编辑版式，其字体由本机 Word 渲染。


## 主题分版与评论

新稿按素材动态组织要闻、经济、交通、民生、建设、社会、生态、评论等主题，最多八个非空版。不要求每天凑齐，每版可有消息、简讯、分析、评论。大事件配评论时须有明确论据与观点，建议与条件推论不能冒充已经实现的效果，不虚构采访、专家、市民反应或官方来源。版面组织参考真实综合日报的主题分工，例如[人民日报的要闻、经济、民生与评论版](https://paper.people.com.cn/rmrb/pc/layout/202607/03/node_01.html)，不使用其报头或署名。

报纸上方点击版面目录，底部可翻上一版/下一版。Word 按相同主题顺序分页，保留体裁标签与完整文章；长文可能溢出为续页，不保证不同渲染器的物理分页完全相同。历史单版兼容，不自动改写旧刊。要应用新版编辑与分版须重新生成，重新导出仅保留原成稿。

旧默认编辑方针自动更新，自定义方针保留。正文不解释施工标记、观测区间与采集缺陷，证据不足的结论直接不写。命中技术/免责模板措辞时成稿不缓存、不发布，显示错误后可手动重新编印，不自动重复付费请求。

## 线路运营与财政修正

客运线路在独立分帧轮次检查，完成后间隔一游戏分钟，不等待整座城市实体校对。支持地铁、公交、有轨电车、铁路、客船/轮渡等原生客运线路，读取真实名称、启用状态、不同停靠点/站台数、票价与正在提供服务的车辆。排除试车、返场、虚拟、停用或退出线路的车辆；仅配车或线路设置不证明实际服务。停靠点去重，不能直接解释为车站建筑数量。

载入既有线路只确认现状，不追认当天新开。载入后新建线路出现实际服务证据时记录投入运营；明确停用、恢复、调价、改名与停站调整形成独立事实。同日后续调整不会抹掉开通记录，车辆短暂无服务不会反复报新开。旧版从未观测到的开通日期无法补造，但更新后的实际服务可作为现状报道素材。其他模组完全替换的线路机制仍需单独验收。

beta.4 将原生正支出加到了收入上，造成结余错误；beta.5 已改为收入减支出。旧 city/monthlyBalance 指标及突破被排除在新稿之外，正确的 city/monthlyNetIncome 单独建立高位基线。旧日志、缓存与原报纸保留用于追溯，新版缓存键不复用旧稿；旧刊不会自动更正，需重新生成。财政数值仍以原生预算面板来源为准，扩展财政模组的独立账目不保证采集。
