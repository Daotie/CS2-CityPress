# CityPress 城市日报

都市：天际线 II 新闻模组，开发版 0.2.0-beta.8。已针对游戏程序集编译；尚未完成完整游戏内验收，不保证覆盖所有玩家动作。安装新版本后必须退出并重启游戏，内存中已加载的旧程序集不会自动更新。

## 使用

解压 `dist/CityPress-0.2.0-beta.8.zip` 全部内容到 `%USERPROFILE%\AppData\LocalLow\Colossal Order\Cities Skylines II\Mods\CityPress`，在本地模组环境启用。不要只复制 DLL，界面资源和 Templates 目录也必须安装。发行包不自动安装、不修改游玩集。

进入城市后点左侧报纸按钮，打开“编辑部设置”，设置兼容 API 地址、模型和密钥后保存；初始默认 DeepSeek。官方 DeepSeek 地址也支持启动前设置 `DEEPSEEK_API_KEY`。密钥不会出现在城市存档、日志或界面状态回传中，输入框不会回显已保存密钥。

面板右上角持续显示当前游戏日期与时分秒，刷新频率为每秒四次，暂停时跟随游戏时钟停住，阅读历史报纸不会改用旧刊时间。城市时间尚未就绪时显示“正在同步”，不创建日志或调用生成接口。加载旧存档会移除初始化产生的 0001 年无效日期，历史列表也会过滤无效日期文件名。

默认不开启自动生成，后台仍记录操作。点“生成本日新闻”生成当前游戏日期的报纸；档案馆可以补编已记录的日期。开启每日自动发行后，在游戏日期前进时编印上一日期并弹出阅读面板。不会生成安装前或未观测到的历史日。运行中单次生成串行，自动任务按日期排队，失败后可手动补编。

报头留空时为当前城市名加“日报”；填写后使用自定义名称。设置可应用于当前存档，或设为全局默认并让当前存档继承；其他有独立设置的存档不受影响。可恢复全局继承。开关、报头、模型和编辑方针均随此范围应用。

## 内容与缓存

重复类别和详情合并，保留次数、首次和末次发生时间。取消 500 种操作截断，有效操作完整进入编辑素材；城市指标保存首值、末值、极值、采样次数和观测时间。完整汇总保留在本地和存档。模型根据可编辑方针自主决定栏目、篇数、合并与舍弃；不强制每日栏目与新闻事件。极端情况下素材超过单次编辑容量，会明确提示并保留全部本地记录，不静默删掉低频事件，也不发起付费请求。

本地成稿缓存包含存档标识、模型、编辑方针、城市名、报头、日期和事实汇总。相同事实直接读取成稿，只有采样次数增加、指标没有变化时也复用；事实变化会重新生成。固定提示前置、变化数据后置，以利用 DeepSeek 自动前缀缓存；实际命中取决于服务端，阅读页展示服务实际返回的命中或用量，未返回不假报，不能保证每次命中。

游戏暂停不会导致额外日刊；生成不阻塞游戏主线程。切换或重载存档会取消旧请求，旧请求结果不得发布到新会话。不同存档按保存于游戏存档内的随机标识隔离；从同一存档另存的分支继承该标识，因而共享本地档案目录，输入不同仍有独立缓存。

## 存储

根目录：`%USERPROFILE%\AppData\LocalLow\Colossal Order\Cities Skylines II\ModsData\CityPress`

- `settings.json`：全局编辑设置。
- `key.dpapi`：旧版当前 Windows 用户加密的 DeepSeek 密钥，保留迁移。
- `credentials/<地址哈希>.dpapi`：按归一化请求地址隔离的加密凭据，不写入游戏存档。
- `cities/<存档标识>/journal.index.json` 与 `journals/<日期>.json`：约每十秒后台更新当前日备份，历史日不反复重写；旧 `journal.json` 保留。
- `cities/<存档标识>/cache/`：通过验证的成稿缓存。
- `cities/<存档标识>/issues/<游戏日期>.json`：游戏内档案副本；`exports.json` 记录报纸实际导出位置。
- 系统文档中的 `CityPress/<报纸名称>/存档-<存档标识>/<日期>.docx` 与 `.json`：默认导出文件。同日期在同目录重新生成会更新当日期刊。文档位置跟随 Windows 重定向设置。

在“编辑部设置”的“报纸导出目录”填写完整文件夹路径，留空恢复默认；设置可应用于当前存档或全局。新目录用于后续导出，旧报纸保留原处；阅读历史报纸后，“打开导出文件夹”打开它的实际位置。“导出当前报纸”可将已有成稿另存到新目录，不调用 API。旧版 AppData 中的报纸仍可阅读和打开原目录。

日志和当前存档设置嵌入游戏存档。本地 journal 是额外备份，不会自动覆盖读取的游戏存档，避免读旧档时引入未来操作。Word 导出直接套用随包的 `Templates/newspaper.docx`，与游戏内报纸统一的纸色、左右版签、行楷报头、日期栏、正文分栏和随文版脚；可以在 Word 中调整模板样式。只有本地文件保存成功后才发布报纸。Word 不嵌入游戏截图。

## 采集范围与待验收事项

通用挂钩观察游戏 ToolOutputSystem 的 Apply 阶段，记录工具标识与预制体名称，覆盖经此管线提交的道路、建筑、分区、拆除、地形等工具动作。它不是逐实体的工程量测量，连续刷子可能产生多次提交，最终是否成功建成还需游戏内验收；不会把次数解释为道路长度或建筑数量。

当前版本接入原生管理按钮采集，涵盖符合管理动作规则的税务、预算、收费、政策、贷款、购地、设施升级/拆除/迁移、线路设置与手动改名。政策、设施等实体参数优先解析自定义名和本地化资产名。贷款记录的是申请调整后的目标总额，并另外观测实际余额，不把申请额写成新增借款。自动车辆状态与通用改名接口仍不监听；相机、选择、面板导航、预览、设置与账户界面不采集。原始读取器参数不会为记录而二次消费，无法展开的参数不猜测。

新增独立城市观测：在 ModificationEnd 检查建筑、路网边、区域、公共交通线路和树木实体的新增/移除；跨帧进行快照校对，完成后间隔 5 游戏分钟启动下一轮，观察施工、废弃、损毁、火情、政策、附属升级和线路票价/选项变化。载入现有城市先建立基线，现有设施不会被误报成新建。实体新增不保证投入运营，路网边不等于完整道路；不把自动生长与自动路网拆分归因于玩家。附属实体不重复计为独立设施，升级通过主建筑记录校对。

读取城市事件档案，保存事件进展、伤亡、损失和城市影响的累计观测，明确禁止把同一事件的累计值反复相加。基线前的旧事件不作为新发生事件；仍在进行的旧事件在数值变化时记录后续。

统计快照遍历当前游戏已登记的全部城市统计类别与参数，包含人口、经济、税收、就业、教育、健康、幸福、迁入迁出、治安、客货运、旅游等实际可用指标，同时保存原生样本与汇总值、统计口径和单位；另读市库、贷款余额、解锁用地、交通流畅度/流量、供电需求/供给/储能、供水与污水处理、气温及雨雪状态，以及空气/土壤/噪声污染栅格的平均、最高强度和非零占比。污染范围为全地图，不冒充城区人口暴露值或现实的 AQI、浓度、分贝。原生统计有自己的刷新周期；每 5 分钟读取并不意味着游戏数据也每 5 分钟更新。未解释的参数和单位可存档辅助核对，但不能编成新闻数字。

采集和刊发分开：有效素材先留存，编辑部再按新闻价值取舍；发送变化指标与人口/市库/贷款/用地等背景值，不把未变指标和原生单样本/汇总值重复塞进稿件。没有变化的快照不会单独触发生成。完整采集仅指已接入数据源的有效信息，不保证接管所有第三方模组内部动作。短于快照间隔的中间状态、没有通用提交入口的自定义操作、无法读取的内部数据可能缺失。兼容面板显示接入数量和采集异常，不把未确认内容当作覆盖成功。

需要在游戏内继续验收：新建/载入/另存、暂停跨日、多个日刊排队、切城取消、工具取消与失败提交、每类管理动作、第三方模组冲突、原生 Cohtml 下的滚动与弹窗。没有使用真实 API 密钥执行付费请求；网络协议、缓存和错误响应以可控替身测试。

## 重大突破与性能

检测常住人口、市库余额、月度预算总收入、月度预算收支结余、家庭数、当前在城游客和解锁用地的整级突破，以及月度预算由亏转盈。例如人口越过 40 万、45 万、50 万会形成事实素材；同一天多次越线合并保留最高一级。首次读取只建立基线，历史最高值随存档保存，数值回落后再涨回不会反复报。安装前或未观测区间的历史不追认，也不声称城市史上首次。无限资金显示值不作为财政突破。月度预算收入不是本月已结算收入，结余不是市库余额；原生单位未解释的数据不用于编造突破。

突破独立进入编辑素材和缓存；即使没有其他操作也可触发编报，默认仍只在手动点击后生成。模型必须将重大突破纳入正文，可与相关事件合并，避免逐条播报。

指标、事件、污染和实体校对分帧执行；报纸生成、Word 导出、档案读取和分日日志写入在后台执行。实时时钟独立更新，避免每次时钟跳动重绘整张报纸。兼容情况面板显示近期采集切片峰值耗时。分帧数量与时间目标不保证所有原生调用都在预算内：游戏任务等待、实体列表复制和大规模瞬时建设仍可能出现耗时尖峰，实际帧率需在真实存档继续验收。

## 编辑流程、独立评论与质量检查（beta.8）

生成过程固定为：城市数据采集 → 事件识别 → 新闻价值评估 → 选题与文章分配 → AI 写作 → 文章质量检查 → 版面规划 → 排版 → 保存与导出。采集数据不会全部直接变成新闻：编辑价值从突破、线路服务变化、管理操作和指标变化评定为一般、重要、重大、里程碑、特别重大等级，只把值得报道的内容交给模型。

**版面数量由程序决定，而不是模型。** 模型返回扁平文章列表或单一“综合”版时，规划器按主题拆分为要闻、经济与财政、城市建设与交通、民生与社会、环境与观察等版面，评论专版始终独立排在最后。只涉及一个领域或素材很少的一天仍是一版，不为凑版生成空白或低质量内容。每篇稿件只会出现在一个版面，不重复占据普通新闻位置。**版面也不再“一类一版”**：同一主题素材足够时连续加版（版名“（续）”“（续二）”等），按编辑容量拆页；新闻版最多十个，超过上限才合并薄版。

**评论专版。** 评论版以一篇长评论为主体，占据该版全部或大部分篇幅，可用 2 至 4 个“## 小标题”分层；同版可放至多两篇侧栏短评。长评论与短评按不同标准检查：长评论要求篇幅、论证、分段和小标题层次，短评只要求观点明确、篇幅适中；只有短评或长评论过短时不会通过验收。版式使用“长评论加短评”专版，长评论在主栏连续排布，短评在窄侧栏，正文不会因小标题而重复。

**重大事件独立评论。** 当存在达到评论标准的重大事件且有足够事实支撑时，先正常生成新闻，再由单独的一次评论 API 请求撰写独立评论；校验篇幅、分析论证、虚构来源和与新闻的重复度，若不合格会带上具体问题重试一次。评论成功后才放入独立评论版；失败会显示明确错误、不缓存，也不会把只有新闻的报纸当成完成品。评论与消息是不同文章对象，随报纸保存、重新打开和 Word 导出保持一致。素材仅有单个阈值、缺少其他事实时不会强行生成评论。

**质量检查。** 排版前检查数字能否追溯到本期采集数据（允许四舍五入及万/亿、百分比写法）、是否出现虚构采访或消息来源、是否有雷同开头与机械评价、是否重复报道同一事件、评论是否只是重抄新闻，以及标题、体裁、分页结构、小标题格式等。检查按事实准确性、新闻价值、语言、结构、分析深度、标题和去重版面等维度评分；发现问题最多进行一次性局部修订（只改有问题的稿件，不整份重写）。修订后仍有严重事实错误的稿件会被删除而不是发布；若删除后没有可刊发内容，则明确报错。每篇稿件的来源、评分、问题与修订次数作为内部元数据随报纸保存，不显示在正文中。

**缓存与旧报。** 缓存规则为 v8，旧版成稿不会被复用；历史报纸仍按原版式阅读和重新导出，不会因为质量规则升级被自动改写。要应用新流程需重新生成对应日期。Word 按规划后的全部主题版显式分页导出，小标题以较小字号标题样式导出并保持与后文同页。

**关于此前“只有综合版、没有评论版”的说明。** 现场日志显示游戏自 10:56 起运行内存中的 beta.4 程序集，而 beta.6 文件到 12:52 才写入 `Mods/CityPress`；13:08 生成的报纸实际由旧 beta.4 代码产生。beta.4 没有分版与评论功能。beta.6 也存在扁平文章回退、缺少独立评论任务和质量检查等真实缺口，本版一并修复；验证前请退出并重启游戏。

## 主题分版与评论

新稿按素材动态组织要闻、经济、交通、民生、建设、社会、生态、评论等主题，新闻版最多十个。不要求每天凑齐，每版可有消息、简讯、分析、评论。**一版不再限制只放一类新闻**：同一主题素材多时会连续加版，版名依次为“经济与财政（续）”“（续二）”等，页面按约 2400 字的编辑容量拆分；只有超过版数上限时才把薄版合并到其他版面。素材少时仍保持单版或合版，不为凑版注水。

评论版是独立的评论专版：一篇长评论占据该版全部或大部分篇幅，可以用 2 至 4 个小标题分层，正文中以单独一行“## 小标题”书写；小标题在游戏预览和 Word 中显示为独立标题块，不会在正文里重复。评论版还可以有至多两篇侧栏短评（约 150 至 350 字），长评论与短评使用不同的质量标准和版式，只有短评的版面不能冒充长评论。大事件配评论时须有明确论据与观点，建议与条件推论不能冒充已经实现的效果，不虚构采访、专家、市民反应或官方来源。版面组织采用综合性日报常见的要闻、经济、民生与评论分工，不使用任何现实报社的报头、署名或版式复制。

报纸上方点击版面目录，底部可翻上一版/下一版。Word 按相同主题顺序分页，保留体裁标签与完整文章；长文可能溢出为续页，不保证不同渲染器的物理分页完全相同。历史单版兼容，不自动改写旧刊。要应用新版编辑与分版须重新生成，重新导出仅保留原成稿。

旧默认编辑方针自动更新，自定义方针保留。正文不解释施工标记、观测区间与采集缺陷，证据不足的结论直接不写。命中技术/免责模板措辞时成稿不缓存、不发布，显示错误后可手动重新编印，不自动重复付费请求。

## 线路运营与财政修正

客运线路在独立分帧轮次检查，完成后间隔一游戏分钟，不等待整座城市实体校对。支持地铁、公交、有轨电车、铁路、客船/轮渡等原生客运线路，读取真实名称、启用状态、不同停靠点/站台数、票价与正在提供服务的车辆。排除试车、返场、虚拟、停用或退出线路的车辆；仅配车或线路设置不证明实际服务。停靠点去重，不能直接解释为车站建筑数量。

载入既有线路只确认现状，不追认当天新开。载入后新建线路出现实际服务证据时记录投入运营；明确停用、恢复、调价、改名与停站调整形成独立事实。同日后续调整不会抹掉开通记录，车辆短暂无服务不会反复报新开。旧版从未观测到的开通日期无法补造，但更新后的实际服务可作为现状报道素材。其他模组完全替换的线路机制仍需单独验收。

beta.4 将原生正支出加到了收入上，造成结余错误；beta.5 已改为收入减支出。旧 city/monthlyBalance 指标及突破被排除在新稿之外，正确的 city/monthlyNetIncome 单独建立高位基线。旧日志、缓存与原报纸保留用于追溯，新版缓存键不复用旧稿；旧刊不会自动更正，需重新生成。财政数值仍以原生预算面板来源为准，扩展财政模组的独立账目不保证采集。


## 自定义 API 与长评论

在“新闻生成服务”填写基础地址（如 https://example.com/v1）或完整 /chat/completions 地址，并填写服务实际提供的模型名称。普通根地址自动添加 /v1/chat/completions，DeepSeek 根地址使用其官方路径。支持 Chat Completions 请求/响应结构；其他原生协议、API-key 查询参数、Azure 的 api-version 查询与特殊自定义鉴权头不在本版支持范围，可使用兼容网关。地址只保存配置，不触发连接，生成时才发送城市素材。

鉴权采用 Bearer API 密钥；无需鉴权的本地服务可关闭。密钥按最终请求地址加密，同一地址在本机账户下的各存档共享；基础地址与对应完整地址共用凭据。更换服务须配置该服务的密钥，原服务密钥保留但不会发送至新地址。更改地址会清空尚未保存的密码框；恢复继承不更改密钥。旧 DeepSeek key.dpapi/环境变量仅在正式 HTTPS DeepSeek 路径使用。设置可应用单存档或全局；API 地址会随设置保存，密钥独立保存在本机。

“接口兼容选项”可关闭 response_format JSON 参数，选择 max_tokens 或 max_completion_tokens，设置512至65536输出上限与15至600秒等待。默认输出8192、等待180秒；实际允许范围以服务/模型为准。参数不受支持会显示错误，不自动改参数或重复请求；截断稿不缓存。模型即使关闭 JSON 参数，仍须按提示返回完整 JSON 报纸。使用自定义服务前应了解其数据处理与费用；新版本不会替你执行真实试用请求。

接口依据：[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/) 与 [Ollama 的兼容接口](https://github.com/ollama/ollama/blob/main/docs/api/openai-compatibility.mdx)。这些文档说明协议，不代表本模组已对所有服务或模型做过真实验收。

开启“重大事件安排独立长评论版”时，以最值得讨论的一件事展开论证，素材足够通常700至1400汉字，分自然段并用2至4个“## 小标题”分层；素材不足时可缩短但不能注水，长评论达到约500字而无小标题层次时会被质量检查要求修订。评论与消息分版，长评论占据评论版全部或大部分，同版可带至多两篇侧栏短评。真实字数和文风取决于模型及输出额度；多版长文可能需要提高额度或等待时间。生成仍默认手动。

## 多版式选择

- 通栏头条：全宽标题和导读，正文分栏，适合综合要闻。
- 侧栏主稿：主稿与标题在较宽的一侧，其他稿件位于侧栏。
- 纵向头条：短标题位于纵向侧栏，报道在旁边展开；不适合过长标题。
- 综合短讯：较小头条融入首栏，适合多条短消息。
- 长评论专版：标题、导读从首栏进入，长正文连续分为两至三栏，不重复文章。
- 长评论加短评：长评论与小标题占两栏主版，窄侧栏编排短评，适合“一篇主论＋若干短评”的评论版。

“按内容选版”依据文章数、主稿占比、标题长度和评论篇幅选取；“适度随机”通过刊物内容的确定性变换在合适模板中选取，保证不同内容有变化、相同成稿可重现。长评论优先专版；有短评时优先“长评论加短评”。具体布局和内容块范围保存于成稿，预览、缓存、重新打开和导出不会重新抽取。旧稿无布局计划时使用原通栏版式，重新生成才应用新模板。

Word 与 UI 共享保存的版式计划和正文段落范围，保证栏宽关系、顺序和内容对应。Word 使用原生竖排，游戏预览使用纵向字列；字体、长标题换列及物理分页会因渲染器不同而有差别，长篇仍可能形成续页。不要把不支持 API 地址配置的旧版本用于新服务设置；旧客户端不会识别新增地址参数。
