# CityPress architecture / 架构

- `Core/Models.cs`: save-compatible daily records, duplicate aggregation, metric extrema and storage.
- `Systems/ActionHooks.cs` and `GameplayBindings.cs`: tool submissions and stock gameplay management callbacks. Recorder failures must not break the original game action; callback exceptions retain their original type.
- `Systems/CityObserver.cs`: observed world changes, event journals and five-game-minute metric snapshots. Loading establishes a baseline instead of reporting the existing city as newly built.
- `Core/EditorialInput.cs`, `CapturePolicy.cs`: exclude known noise by origin, while retaining real construction involving transport boarding areas.
- `Core/NewsValue.cs`: editorial brief and value grading (routine/notable/major/milestone/critical) over breakthroughs, transit changes, actions and metric deltas, plus the commentary-trigger decision and the verified fact sheet reused by commentary/revision prompts.
- `Core/PagePlanner.cs`: deterministic edition planning after the model response. Extracts commentary from mixed pages, splits flat or single-"综合" output into themed editions, splits same-topic material over the editorial page capacity into（续）editions, merges duplicate themes only while the result fits, bounds news editions using PaperLayout.MaxNewsPages, never emits empty pages and always keeps commentary last. Commentary articles are ordered by length and marked as 长评/短评.
- `Core/QualityControl.cs`: pre-layout quality gate. Traceable-number matching, fabricated-source detection, mechanical/repeated openings, duplicate-story and commentary-overlap detection, role-aware commentary checks (lead long commentary needs paragraphs and 2–4 subheadings once it is long; short comments use their own standard), weighted scoring and per-article audit metadata; applies safe degradation for unsafe copy.
- `Core/NewsService.cs`: orchestrates the pipeline — primary news/opinion generation, full-manuscript revision with add/rewrite/merge/delete operations, bounded specialist commentary fallback, factual supplementation, review/degradation, layout assignment, then cache. Configurable compatible-service payload, cache and usage accounting live here. Unchanged resampling does not invalidate a factual cache. No API call for noise-only days; incomplete opinions or malformed/truncated primary drafts are not cached as complete manuscripts; accepted news can still publish.
- `Systems/NewsSystem.cs`: UI state, per-save/global preferences, time rollover, cancellation and archive-before-publication. User-facing status is emitted as a stable `CityPress.Status.*` key plus arguments rather than formatted text.
- `Core/I18n.cs`: active game locale, Chinese/English content-language detection, localized user-facing exception keys and the `I18n.Say` fallback used for diagnostic collection summaries. `lang/en-US.json` and `lang/zh-HANS.json` provide keyed UI strings, while `UI/src/i18n.ts` uses `cs2/l10n` and an imported fallback table so missing language files never render raw keys. `Core/DocxExporter.cs` selects Word furniture and date format from the language detected in the issue itself.
- `Resources/paper-layout.json`, `Core/PaperLayout.cs`, `UI/src/paper-layout.ts`, `Templates/newspaper.docx`: shared newspaper layout and editable Word export. `opinion` handles one continuous long commentary; `opinion-mixed` gives the long piece two main columns with subhead blocks and short comments a narrow sidebar. Commentary subheadings are ordinary body lines prefixed with `## `, exposed as `subhead` layout blocks and rendered as smaller heading paragraphs in Word with keep-with-next.

The save envelope remains version 1 with additive metric and `OmittedEmptyDays` fields. Empty past initialization days are omitted only when they have neither actions nor sampled metrics. Their issue-list suppression survives reloading without deleting archived files; a genuine current day with that date remains valid. Previous auto-renaming noise is filtered when generating new issues. Actual observed coverage is narrower than every internal game/mod event. Read [the collection guide](USER_GUIDE.zh-CN.md) before interpreting action counts as engineering quantities.

记录、观测、筛选、生成与排版分别维护。工具提交次数不代表建成数量；原生路网边不代表整条道路；事件累计数据不可相加。存档版本保持 1，新字段向后兼容。新增覆盖应同时补充文档、缓存规则和相应验证。

- `Core/Milestones.cs`: trusted scalar high-water marks, per-day merged thresholds, persisted in the game save. Baselines do not generate historical claims.
- `Core/ExportStore.cs`: archive-first persistence and configurable Documents exports with a per-save location index; locked Word targets get a unique copy, blocked export directories fall back to the local archive, and filesystem failures return the completed paper with explicit status flags.
- `Core/JournalSnapshot.cs` and `JournalStore.cs`: immutable worker snapshots, per-day journal files and a lightweight version-2 disk index. The game-save envelope remains version 1.
- Observer reconciliation is staged with row/time targets; native query allocation/job synchronization is still synchronous. Clock and full UI state have separate bindings.

- `Core/TransitFacts.cs`: line-level service evidence, baseline-safe transitions and same-day merged changes. CityObserver stages an independent one-game-minute line cycle, using actual vehicle states rather than assignment counts.
- `Core/FinanceFacts.cs`: signed monthly balance uses income minus the positive native expense-array sum. Old erroneous monthlyBalance samples/highs are excluded from v5 editorial facts; monthlyNetIncome has a clean baseline.
- `Core/EditionRules.cs`: normalize themed pages and legacy flat articles, tolerate empty editions from a model instead of rejecting the issue, distinguish genres and reject process caveats. `Pages` is authoritative when present; `Articles` is flattened for backwards-compatible readers. Theme order is shared by UI and Word.
- `Core/Models.cs` also carries beta.7+ audit metadata (`QualityIssue`, article sources/score/status/revision, commentary role, newspaper quality score and layout version). It is additive and ignored by older readers; it never appears in the rendered paper.

- `Core/ApiOptions.cs` and `Systems/ApiKeys.cs`: normalized compatible endpoints, bounded request options, endpoint-scoped DPAPI credentials and restricted legacy DeepSeek migration. Keys/endpoint metadata never enter editorial input. Redirects are disabled.
- The versioned cache key includes endpoint/model/output/JSON/layout/quality options; older caches are ignored after the commentary/page-planning changes. A saved PageComposition is authoritative for UI and Word; body blocks refer to article/paragraph ranges (including `subhead` blocks) to avoid storing another full text copy. Old issues fall back to the banner composition.
- JSON and Word writes go through `Storage.Commit`: atomic `File.Replace` when available, otherwise a delete-and-move fallback when sandboxed/network filesystems deny replacement.
- Six composition templates share Resources/paper-layout.json. Opinion paragraphs are balanced across continuous columns; `opinion-mixed` balances the long commentary over two main columns with subheads and puts short comments in a narrow sidebar. UI vertical glyph columns avoid relying on Cohtml writing-mode support; Word uses native tbRl text direction.

- `Core/PublicationRepair.cs`: supplements missing verified transit openings and milestones after review; rebuilds briefs from prepared facts if usable model news is absent. It never fabricates a long opinion to satisfy an acceptance gate.
